# 历象 R8 · 设计与iOS接入规格

仅设计／独立原型交付；不改App、不做App构建、不提交、不提审。build12仍内测。R7动画已由用户批准，本轮只改变自适应容器。

## 1. 页面与日期

只有iPad把首页与单日内容合屏。普通iPhone只有portrait；Duo各显示大小维持首页→单日的独立层级。首页含Hero与月历，日期点击进入单日；iPad选日期更新合并页。

Hero三柱完整显示“丙午年／己亥月／庚寅日”，本轮还显示巳时辛巳与09:41样本时间。真实时柱需要随用户查看的时刻更新，不能把设计样本写成常量。原型数据固定2026-11-12，其他日期选择只演示导航并提示样本边界。

当日岁时和纪念日只在命中时显示，每项有独立链接，避免与Hero主区域点击混淆。今日岁时→岁时tab内该活动详情；纪念日→倒计日tab内该记录详情。无命中不保留空行。原型已给出命中／无命中两种状态。

## 2. 月历与tab提醒

月历单元51pt：公历数字、农历／节气文字、标记轨道各占独立位置。标记轨道顶41pt，文字底37.5pt，保留3.5pt空隙；星和点并列，不叠在农历文字上。

岁时红点：事件仍在今日或未来、距离0–10天（含第10天），有新解锁未读版本。阅读页成功载入该eventID＋contentVersion后才读掉；进入tab但没看正文不清掉全部红点。新版本可再次提示。

倒计日红点＋数字：取0–10天内最近的剩余天数；0代表今天，3代表最近还有3天，不表示3条记录。没有临近事项时隐藏。App内提醒与系统通知权限无关，拒绝通知也不能消失。原生无障碍描述应读“今天有纪念日／最近还有X天”。

## 3. 天气与定位

自动确定所在城市需要“使用App期间”定位权限；只展示天气不需要持续后台定位。

状态：未询问→用户点击“使用当前位置”→系统定位弹窗→定位中→城市天气就绪；拒绝／受限→保留替代panel与设置入口；已定位但网络失败→重试panel。拒绝不阻断日历、经文、黄历等功能。获得定位后恢复之前认可的“8°多云／上海”卡片视觉，数据仍应由实际天气服务返回。

HTML弹窗是设计示意，不使用浏览器Geolocation API，不向本机请求定位。iOS需配置用途文案，由Core Location授权回调驱动状态；从设置返回后重新读取授权并加载城市天气。定位失败与天气网络失败分开处理，不编造城市。

## 4. iPad布局

横屏Hero插画由180pt增至270pt，增加节气图露出；完整日期、干支、当日入口与经文保持可读。中列为黄历摘要＋岁时＋择日上下排列；右列月历下放紧凑快捷项，利用下半屏空间。必要的长内容可在各列继续滚动，不把主要导航挤出屏幕。竖屏用全宽横向Hero和下方两列。

## 5. 岁时详情：native与Web

| 原生界面 | 网页正文 |
|---|---|
| 返回与tab、日期/分类/标题、解锁判断、分享入口 | 节气大图、文章标题与导语、来由/地方习俗/仪式步骤 |
| 加载、离线、缓存提示、重试、链接路由 | 来源、图片alt、内容更新时间、可访问的段落结构 |
| eventID/contentVersion、权限与外链处理 | 不制作第二套App导航、不申请系统权限 |

窄屏：原生摘要上方固定，WKWebView占剩余可用空间并负责正文滚动；不叠加另一层正文滚动区。宽屏：原生摘要在左，正文在右。网页最大阅读宽度880px，正文17px，随字号与暗色tokens调整。加载失败不把空白WebView当成成功，也不提前读掉解锁红点。

本地原型的iframe模拟WKWebView，指向webpages/；没有连接主站admin或远程接口。模板、schema、JSON样本、渲染器和内容提示词在templates/。正式工具应由结构化数据生成HTML，编辑确认来源、图片和版本后再发布；本轮内容是设计样本，来源尚未编辑补齐。

原生应在请求正文前完成解锁／日期／版本判断，后端也遵守内容开放规则；不能只在网页上隐藏文字。过去的item从岁时列表消失，首页只推荐未到且小于15天的最近项目（沿用之前规则）。

## 6. 首次纪念日与通知

先把记录保存到本机，再说明提醒价值；用户主动点“开启系统提醒”后，才调用系统通知授权。

- authorized（包括系统允许的provisional/ephemeral）：创建该记录下次有效日期的通知请求。
- notDetermined：明确开启才请求；“暂时只在App内提醒”不等于系统拒绝。
- denied：不重复弹系统授权，提供用户主动前往设置的入口。记录与App内临近提醒仍保留。
- 修改、删除或从设置返回后，按记录ID更新／取消对应通知；避免重复注册。

原生排期使用现有CalendarCore计算公历/农历、每年重复、闰日策略及下次未来日期，不能把已过的今天09:00排成过去时间。本轮HTML可保存一条可编辑示例记录并在列表/当日命中中展示；公历天数基于固定样本日期。它仅记录schedule意图（nativeScheduled=false），不会发浏览器或系统通知；农历排期留给原生引擎，不用公历算法冒充。

ReminderPermissionReference.swift提供授权后才add的独立参考，未集成App。系统弹窗文案是示意，正式显示由iOS管理。

## 7. 每日一签已定稿

ApprovedMotionManifest.json冻结原始三份素材、MP4/GIF、1450ms核心脚本和Timeline v3：0–180按下／180–600轻摇／600–1050升签／1050–1450展读。签条角度-2/-1/+1/+2，192pt以下遮挡，主签升起90pt；不重新生图、不更改节奏。

新的host把300×430艺术坐标与原生标题／按钮分开。窄屏上方标题、中间艺术区、下方44pt以上操作；宽屏标题在左、艺术与操作在右。材料随艺术区缩放，文字和按钮不跟着整张930pt画布缩小。结果文案14pt以上，空间不足时滚动阅读，避免签意文字小到无法读。

14种设备/窗口方案均有待机、结果PNG与可交互HTML。真正运行时依据可用空间重新布局，状态和已抽结果随展开／收起保留。本地日期固化与同日同签规则不变，仍没有AI调用。SwiftUI新host是独立参考，只做syntax parse，未进行App编译或原生运行验证。
