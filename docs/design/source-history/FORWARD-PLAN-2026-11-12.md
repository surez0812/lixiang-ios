# 历象 1.0 前进计划 + 职责 + 批评闭环（2026-11-12 定稿）

> 原则：不是"做完就交"，是"边做边批评边改"。任何角色发现问题必须提出来，不改成一坨再上架。

## 一、目标与验收铁律
1. **首屏即说服**：今日大卡、单日详情首屏不滚动就要看到用户想看的核心黄历信息（对标竞品密度），不要瀑布流、不要重复、不要卡顿。
2. **白话要"够"**：每条术语讲清「含义 / 影响 / 今天怎么用」，不是字面翻译；不是只解释一个字。
3. **能留住人**：有每日一签、吉日查询、提醒/收藏这类"每天想打开"的理由。
4. **不造假**：截图/性能/真机证据必须真实，测不了就写 NOTRUN，不许冒充 PASS。

## 二、阶段划分（每阶段出可验收的 build）
- **P0 · build13（打开就看到的）— 最高优先**
  - Hero 今日大卡终版（A 布局 + B 暖色 + 印章 PNG + 分享卡恢复）
  - 单日详情高密度首屏（竞品对标）：宜忌全量 chips（唯一）、五行/值神/冲煞/星宿四格、财/福/喜/阳贵四宫 + 紧凑罗盘、胎神/建除/彭祖/吉神宜趋/凶神宜忌密集行、时辰 12 横条、每日一签 + 吉日查询、全局「白话全解」开关；民俗/天气/更多术语折叠
  - 去重 + 性能（TabView 页数、分享按需渲染、单紧凑网格/少卡、Instruments 证据）
  - 白话 v2（≈359 条，含义/影响/怎么用；冲/煞/冲煞/岁煞补键），8 域全接入
  - 版本号正确（1.0/13）

## 三、每人职责（都要附"批评"义务）
- **PM**：内容完整性与准确性、白话质量、功能覆盖、留存项；负责缺口审计；必须反馈内容/UX 缺口，不许只补内容不看体验。
- **Designer**：视觉/信息架构、首屏密度、人性化与情感、留存点；必须反馈布局/可用性/留存问题，不许只出图不质疑。
- **Dev**：实现、性能、正确性、不造假数据；必须反馈可行性/性能/代码质量风险，发现"规格伤体验"要提，不许闷头实现。
- **QA**：真实行为验证、找缺陷与缺口、不许假 PASS；必须反馈"还没准备好"和用户可见问题。

## 四、批评闭环（每阶段至少一轮）
- 每人在 `reviews/CRITIQUE-ROUND-*.md` 写一段：**我看到的错 / 不足 / 不够人性化 / 留不住用户的地方 + 我的建议**。
- PM 汇总 → Lead 与 Sure 讨论 → 需要改的回到设计/计划 → 再实现。
- 例（已知）：单日详情宜忌重复、白话只讲字面、首屏密度不足、缺乏每日一签等留存钩子——都已立项，后续批评继续补。
