## 二、新单日详情 IA（高密度首屏）

**一个 ScrollView（不嵌套），总高度首屏≈1.2 屏内**：
1. **Hero 紧凑条**（高 ~150，非大图卡）：公历 + **大农历日** + 干支/属相/周数 + 节日 chip；图可缩为背景/侧图（不与信息争高）
2. **宜忌全量 chips**：宜（绿）全量换行、忌（朱）全量换行；每 chip 可点→白话
3. **四格网格**（2×2）：五行 | 值神 | 冲煞 | 星宿（值+白话入口）
4. **方位四宫格**：财神/福神/喜神/阳贵（大字方向「东南」）
5. **吉神罗盘**（唯一入口，高 ~220，可折叠）
6. **密集行组**（紧凑两列/单行）：
   - 胎神：占房床…
   - 建除：建日（白话）
   - 彭祖百忌：甲不开仓…
   - 黄帝纪元：4723 年
   - 吉神宜趋 chips / 凶煞 chips
7. **时辰宜忌横条**：12 格（时+黄黑道点），点格展开该时辰详情
8. **今日一签 / 吉日查询**（留存入口，2 按钮）
9. **折叠（真正次要）**：民俗未来 10 天 / 天气 / 更多术语（默认收）——保留但**移出首屏**
10. **全局「白话」开关**（右上）：展开所有术语/神煞的白话（zh/en），不跳页

设计要求：分区网格、紧凑行高（24–28）、分隔线而非独立卡阴影；亮暗 token ≥4.5；375 首屏见 §2–§7 主干；iPad 两列（左 Hero+宜忌+四格，右罗盘+密集行组）。

## 三、内容审计（317 条逐条）

**问题分类（抽样）**
- A 覆盖缺口：五行（纳音→五行映射）、黄帝纪元、属相/周数、时辰黄黑道逐时吉凶文本、吉神/凶煞全量（仅 61/92 名，未覆盖「宜趋/忌」组合词）
- B 解释质量：现 317 条多为「是什么」1 句；**缺「影响/怎么用」**（如「天德：宜祈福…」→ 应写「适合…；不宜…」）；需每条 **含义+影响+今日怎么用** 3 段（≤80 字）
- C 显示缺口：仅值神/罗盘图例/部分术语有入口；**建除/彭祖/星宿/纳音/胎神/吉神宜趋/凶煞无内联**
- D 准确性问题：凶煞/吉神组合、冲煞方向、胎神方位需与 lunar 库字段核对，禁止自造

**动作**：
1) 扩表：317 → **~450 条**（补五行 5、属相 12、建除 12、时辰吉凶 12×2、吉神宜趋/凶煞全量）
2) 每条改为 **含义/影响/怎么用** 3 段（zh ≤80 字 + en ≤30 words），qwen4 批量 + 人工/双源核对
3) 全部 panel 接入 `panelTerm`（名称旁「白话 ›」）
4) QA 抽检 15% + 专家/宗教合规复核
